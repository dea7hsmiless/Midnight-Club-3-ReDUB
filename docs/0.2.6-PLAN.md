# 0.2.6 — plan

Written 2026-11-22. 0.2.5 ships local multiplayer and a freeze fix; **0.2.6 is the
multiplayer-over-a-network release**, plus the defects 0.2.5 deliberately left.

The rule from 0.2.5 carries over: **a feature ships when it is verified working, on the
hardware it claims to work on, not when it is nearly done.**

---

## The headline: online, with a server

0.2.5 does not describe anything as online, because none of it is. What exists is a
peer-to-peer transport that links copies on one LAN, verified only as two instances on one
machine. 0.2.6 has to answer the question a player actually asks: *can I play with a friend
who is not in my house?*

That needs a server, and the server is the work.

### Order matters

Each step depends on the one before it. Doing them out of order is how 0.2.5 nearly shipped
an "online" claim on top of a loopback test.

**Step 1 — System Link on two real machines.**
Carried over from 0.2.5. Two PCs, one network, host creates a match, the other joins.
This validates the XNet HLE against a real network stack for the first time. Nothing else in
this plan means anything until it passes.
*Done when:* two machines play a race, recorded.

**Step 2 — A relay that works across the internet.**
A small server that receives each player's datagrams and forwards them, so nobody needs a
port forward or a public address. The existing `tools/mc3hub.py` proves the wire format and is
the starting point; it has no relay, no auth and no FAR lists.
*Done when:* two players on different home networks, both behind NAT, see each other's cars.

**Step 3 — Rooms and matchmaking.**
Players find a game without knowing an IP. Create a room, list rooms, join, leave, and the
room survives one player dropping.
*Done when:* a player joins a room from a list and lands in the host's city.

**Step 4 — Free roam on top of it.**
Only now do the free-roam specifics matter:
- FAR lists (map markers for players beyond your direct links) — format documented in
  `roam_core.h`, not implemented;
- hub-side link selection, so linking scales past a handful of players;
- reconnect: a restarted client should re-find the session without relaunching both;
- name tags actually observed on screen (never seen yet; the peer was behind the camera).

**Step 5 — Collisions with other players' cars.**
Remote cars are pass-through today. This needs the game's own collision path, not a shim.
It is the difference between "cars move" and "we are driving in the same world".

**Step 6 — Pedestrian sync beyond ~15 m.**
The proximity approach (Option A) only makes walkers near a streamed pedestrian adopt its
pose. The ghost path exists (`MC3_ROAM_AMBIENT_PEDGHOST`) but is inert and unverified.

## Capacity target: 18 remote cars (owner's ask, 2026-11-22)

Free roam is only worth calling multiplayer if a lobby is worth joining. The target for
0.2.6 is **18 remote cars** on screen.

What that costs, from measurements already taken:

| Item | Figure | Source |
|---|---|---|
| One remote car's heap | ~779 KB | "the cruise's 3 cars took 2338 KB, about 779 KB each" |
| 18 cars | ~14 MB | 18 x 779 KB |
| Free heap after the cruise's own cars | ~6.2 MB of 47 MB | the pool's own "heap after" line |
| Registry capacity needed | 8 player slots + 18 + 2 = **28** | `roam_caps.c` rule |

So 18 cars does **not** fit in the current budget: it wants roughly 8 MB more than is free.
Three ways there, in order of preference:

1. **A larger contiguous window.** `XBOX_CONTIG_SIZE` gates the default (12 on 64 MB, 32 on
   128 MB), and the car heap prefers the window when it has one — "cars heap: none (64 MB
   window)" in the log means it fell back to the main heap.
2. **Trim what the pool holds per car.** 779 KB is the *engine's* car, not ours, so this is
   limited.
3. **Show fewer than you track.** Render the nearest 18 and keep the rest as blips. That is
   what FAR lists are for, and it turns the count into a rendering budget rather than a
   game-state one.

The number is a measurement, not a promise. Known-good today: **2 verified**, **8** plausible
(the game's own player-slot count), **12** configured but already tight.

## The defects 0.2.5 leaves

**Movie-playback freeze.** A second, distinct intermittent hang: the guest blocks inside
Bink's own `NtWaitForMultipleObjectsEx(2, …)` with an infinite timeout, so no frame-progress
watchdog can reach it. The fix has to bound that wait (or remove Bink's thread ownership
entirely); see `docs/0.2.5-SCOPE.md` for the stack and the reasoning. It reproduced once in
three runs, which is why it is not a blind change in 0.2.5.
*Done when:* the intro movies play through N times with no hang, or a bounded wait is proven
to recover without visual damage.

**Aspect ratio polish.** The feature works on all three surfaces. Two cosmetics:
- it stores `fill` for a control labelled "Stretch" — accept both spellings;
- an unrecognised value silently means Auto — warn instead.

Live apply (no restart) is possible but is a behaviour change, so it waits.

**120 Hz stays offered (owner's call, 2026-11-22).** `MC3_ALLOW_120` exists and the setting
cycles 30/60/120; the launcher offers 120 too. There is still no recorded run on a real 120 Hz
display, so the 0.2.6 task is **verification, not removal**: run it on a 120 Hz panel, fix what
breaks, and document the result. Until then the help text must not promise more than we have
measured (it measures frame pacing at the title on a forced 60 Hz machine).

**Frame generation polish.** `Crossfade` is a plumbing test with visible double exposure.
Motion-compensated is the usable one.

## UX carried from the 0.2.5 roadmap (never started)

| Item | Note |
|---|---|
| Saved setups | Save and reload a car/track/settings setup. |
| Save backup | Copy the memory-card image before a session, restore on demand. |
| Controls remap | The 0.2.5 roadmap listed it; no work done. |

These were in the 0.2.5 roadmap as "M5, parallel, low risk" and were displaced by
multiplayer. They stay on the list rather than being quietly dropped.

---

## Explicitly not planned

- **DLSS.** Removed from the UI; `DLSS-MOTION-PLAN.md` is a plan, not code.
- **Vulkan on Windows.** The launcher toggle is gone and the shipped package contains only
  the OpenGL build. `nv2a_vk.c` stays for the platforms that use it.
- **Matchmaking ratings, parties, invites beyond a room list.** Out of scope until rooms work.

---

## What "done" looks like for 0.2.6

A player on one home network creates a room; a player on another home network finds it in a
list, joins, and drives into the same city; each sees the other's car, can collide with it,
and sees map markers for anyone else in the room. Every one of those clauses is something
0.2.5 cannot do today.
